CssContext
  - enthält alle werte aus Theme und EditorConfig, die in CSS Konstanten vorhanden sein müssen
  - kann die Werte in das CSS eines DOM-Knoten überführen

  - verwaltet listener auf bestimmte prop changes
  - erlaubt das überschreiben einzelner oder aller werte


<CssCtx>

  </WindowCtx />
<CssCtx>

Ablauf:
  1. CssCtx start mit null als context
  2. WContext bildet theme und editorConfig und ruft dann init() damit auf
     da CssCtx = null wird abgebrochen (könnte evt. nicht funktionieren)
  3. init setzt die values in der Registry und die CSS-Konstanten auf dem body

  4. User öffnet die Settings
       - Das Modal muss einen neuen CssContext öffnen, welcher mit dem Parent-CssCtx
         initialisiert wird, der dann auf das Modal-DOM applied wird
       - Die Werte im EditorConfig bzw. Theme-Form kommen aus dem entsprechenden Modell,
         welches mit der aktuellen Werten vorbelegt wird
       - Änderungen am Theme- bzw. EditorConfig-Model müssen
         auf den Parent-CssContext über updateProp(...) kommuniziert werden, damit diese
         sowohl auf JS als auch DOM-Ebene im Hintergrund aktiv werden
       - Wird eine Config komplett überschrieben, dann müssen alle Werte von dieser
         gesynced werden, aber nach Möglichkeit nur eine Notification gesendet werden
       - Beim before-Button muss das gleiche beim start und end passieren

       - Wird innerhalb eines ThemeFreeze ein weiterer Modal geöffnet, so muss auch da
         ein neuer Child-CssContext mit Link auf den Parent geöffnet werden. Beim
         schliessen darf dann aber kein Reset auf dem Parent getriggert werden.

       - Wenn der User die Änderungen speichert, dann können diese in den Storage
         übernommen werden, aber am BODY-DOM bzw. parent-CssContext braucht keine Änderung
         mehr gemacht werden
       - Wenn der User die Änderungen abbricht, dann müssen wieder die alten Werte aus dem
         child-CssContext in den Parent-CssContext übernommen werden (+body syncing)

       - Resource-Links:
         Beim AppStart werden die Basis-Hrefs aus den Meta-Block als BaseHrefs gepeichert
         ...nach der Auflösung des Theme kommen neue HREFs hinzu und wenn ein ThemeFreeze
         geschieht, müssen diese bei allen Temp-Änderungen auf den Resource-Links auch immer
         noch beim Sync im Parent dazugesetzt werden. Erst nach dem Speichern bzw. Abbrechen
         darf auf die aktuellen Theme-Werte (mit den BaseHrefs) reduziert werden

     APP-START: Meta-HREFs => Base-HREFS
     CTX-INIT: Theme-HREFs => Curr-HREFS
     STYLE-LOCK: Theme-HREFs => Backup-HREFs

     Link-Syncing:
       a) normal: Base + Curr
       b) locked: Base + Curr + Locked

     Bei Updates auf resources befinden wir uns im Fall b
     Beim Cancel der Settings wechseln wir von b) nach a) wobei curr = locked
     Beim Speichern der Settings wechseln wir auch von b) nach a)


  5. Wenn die App schliesst, dann
       Muss der CssContext alle Props wieder aus dem Body (nur Parent!) entfernen und die
       Resource-Links müssen auf die Basis-Hrefs gesynced werden

    const value = {
        init: (editorConfig, theme) => {
            const values = {};

                switch(type) {
                    'rgb':  /[0-9a-f]{6}/
                    'rgba': /[0-9a-f]{8}/
                    'px':   /[0-9]+/
                    'urls': /".*"/
                    'perc': /[0-9]+%/
                    'float': /[0-9]+.[0-9]/

                if (!regexp) continue;
